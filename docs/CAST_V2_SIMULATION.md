# Cast v2 offline contract

V1 action shapes remain unchanged. V2 cast requires exactly `kind`, `schema_version: 2`, `spell_option_id` and `targets`. Selections are an ordered list of 1 to 16 entries, each exactly `entity_uuid` or bounded finite `position: {x,y,z}`. Order and repeated allocations remain part of the persisted canonical action digest. An option must permit repetition and the target budget/type. No native prototype/source fields, flags, slot-level overrides, item handles, target proxies or resource writes are accepted from the caller. V2 inventory throw is separately implemented in the offline fixture; see [THROW_V2_SIMULATION.md](THROW_V2_SIMULATION.md). Neither variant enables native execution.

`cast_options` is bounded to 64 entries and exposed only for the bound actor. Public fields are opaque id, observed session/revision, concrete spell token, verified fixture slot/resource mode, target budget/types and repeat policy, with optional label. Other players' choices and private source records are removed. The offline simulation contains explicit fixture spellbook choices, including two sources of one weapon prototype and explicit higher-level fixture prototypes. Their names and costs are simulation fixtures, not claims about BG3's actual spellbook or native targeting semantics.

Simulation option IDs hash the bound actor and exact current choice record, including session, revision and private source identity. Changes reissue the token. The executor rechecks the ID and exact private catalog record immediately before legality/cost checks; a source swap or forged cost variant cannot silently reuse a prior meaning or pay a different slot. Upcasting selects an already recorded concrete fixture choice rather than synthesizing a prototype name or changing UseCosts. All target/resource checks precede deductions; repeated projectiles pay the fixture cast cost once and apply their ordered allocations. Position selection denotes an area center, leaving fixture effects to the simulator.

Simulation declares `action_contract_versions: [1,2]`, `cast_multiple_targets: true` and `cast_upcast_options: true`, with `simulation_only: true`; `throw_inventory_item` now has its separate simulation capability, while dialogue stays false. CompanionService separately gates observed choices and multiple allocations, and normalizes unvalidated native versions/features closed. Native research preparation/execution explicitly parse only v1 and reject v2 before invoking the engine evaluator. Existing native action capabilities remain false.

The journal currently persists the canonical opaque option ID plus ordered selections, and its session/action scope. This is sufficient for the fixture's deterministic identity map, but it does **not** journal a complete resolved native SpellMetaId/source/cost variant. A future native v2 adapter must durably record the actual resolved choice identity with the observation scope before enqueue, revalidate the original choice in the same engine call, and poll its original identity after reload. It must not resolve an old token against a newer catalog, choose the first duplicate prototype, or promote fixture flags to native acceptance. Native observations, option resolution, multi-target/upcast normal costs, reaction/concentration paths, target-removal races and multiplayer remain unvalidated.
