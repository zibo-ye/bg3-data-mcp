# Opt-in developer execution

`NativeResearchExecution` is separate from NativeBackend, the companion service and restricted MCP. Production capabilities remain disabled. Its self-Dash/EndTurn module paths and a zero-AP targeted rejection now have limited independent-campaign live evidence. Successful targeted execution by this module and the new explicit reconciliation path still require their own live tests.

```python
from bg3data.companion.native_execution import NativeResearchExecution

executor = NativeResearchExecution(allow_execution=True)
submitted = executor.submit(actor_uuid, observed_session_id,
    {"kind": "cast", "spell_id": "Shout_Dash", "target_uuid": actor_uuid}, request_guid)
result = executor.poll(actor_uuid, observed_session_id, request_guid)
```

Submission research actions are self Shout_Hide, self Shout_Dash, own EndTurn and explicitly attested Projectile_MainHandAttack targets. Submit must explicitly opt in. A cast requires an already installed active matching `NativeRequestTrace`, room for further bounded records, and exact actual SpellBook source metadata. Every new submission checks the observer epoch, recruited non-avatar actor, positive host owner, death/combat state, active usable turn, explicit false end-turn flags, and an idle destination queue in the same server call that appends. No bypass flags or scripted casts are used. Zero action points do not cause an invented local rejection: normal engine rejection is still recorded.

Targeted submission additionally requires `known_target={"actor_uuid": actor_uuid, "session_id": observed_session_id, "target_uuid": target_uuid, "source": "ordinary_player_observation"}` as a named argument. This is an explicit developer/test-operator attestation of ordinary gameplay knowledge, not an autonomous discovery method. It must match the action, actor and epoch. The same server call verifies a living hostile nonparty/nonavatar target in the same reflected combat, exact true actor CanSee membership, named ServerCharacter Invisible/OffStage flags exactly false, Darkness CharacterSneaking/ActuallySneaking exactly false and Sneaking exactly zero, and absent Invisibility component. Missing fields, unknown membership or positive concealment block submission. The actual source must be WeaponSpell and targeting type Projectile. There is no enemy enumeration, proxy targeting, position targeting or general visibility promotion; output still states `visibility_verified=false`. An attestation plus these restrictive checks is a developer-only research gate, not validated stealth semantics. Target UUID is included in the deduplication payload, and public target HP before/after is recorded when readable.

The SE Lua registry retains at most 64 request entries and never automatically evicts them. Pending and uncertain requests both block further submissions for the same actor/session, including attempts with a new GUID. Reservation occurs before the append. Reusing a GUID with the same payload returns/polls the existing entry, even if the turn has since ended; it never appends again. A conflicting payload rejects. A failed append is uncertain and remains reserved, because a transport/conversion failure must not be treated as proof that nothing happened. Session or authority changes make a pending request uncertain. Stored terminal results remain historical evidence and are not rewritten by later loads or ownership changes. The registry is process/Lua-environment memory, not a disk journal or a replacement for durable service idempotency.

Ordinary polling still freezes uncertain entries. Explicit `executor.reconcile(actor_uuid, observed_session_id, request_guid)` may upgrade an uncertain cast using late exact-GUID lifecycle evidence only while the original trace object remains active, bounded, error-free and in the same epoch, with current actor identity still valid. A stopped/replaced/expired/truncated trace, unknown continuity for an entry from an older executor version, missing or mismatched lifecycle, session change or authority change remains uncertain. Reconciliation reads no new resources or target HP, makes no new causal cost claims, and never appends a request. Completed/rejected results stay immutable even across subsequent context changes. EndTurn has no exact cast-GUID lifecycle and is not reconciled by this path. Mocked tests cover these limits; no live reconciliation proof is claimed.

Self-Shout polling requires the exact request/cast GUID and consistent actor, spell, cast entity, unique queued/started/finished/outcome records, and agreeing known terminal results. `None` is completed; `CantCast` is rejected with no guessed cause; unknown results are uncertain. Missing callbacks remain pending until the bounded trace expires or stops, then become uncertain. Both casts and EndTurn also have a 60-second deadline measured with the source-exposed `Ext.Timer.MonotonicTime`; unresolved evidence becomes uncertain on polling. Records before submission are excluded. Resource snapshots capture before/after ActionPoint and Movement when readable, plus deltas and any matching later CastedSpell event. `costs_verified` stays false because this reducer cannot prove the resource change was caused solely by the submitted request. Terminal evidence is frozen rather than rewritten by later resource changes. No automatic retry is permitted.
